# STM32 主人工程索引

这个文件只回答两件事：工程从哪开、什么时候需要新文件夹。

## 一、打开哪个文件

每个独立程序都有自己的工程文件夹，里面有一个 `.uvprojx`：

| 讲次 | 文件夹 | 双击打开 |
|---|---|---|
| 01 点灯 | `01_led_blink\` | `led_blink.uvprojx` |
| 02 GPIO 模式 | `02_gpio_modes\` | `gpio_modes.uvprojx` |
| 03 按键输入 | `03_button_input\` | `button_input.uvprojx` |
| 04 EXTI 外部中断 | `04_exti_button\` | `exti_button.uvprojx` |
| 05 TIM 毫秒节拍 | `05_tim_tick\` | `tim_tick.uvprojx` |
| 05b TIM 十秒锁机 | `05b_lock_timer\` | `lock_timer.uvprojx` |
| 作业 01 按住亮、松开灭 | `04_button_hold_ryan\` | `button_input.uvprojx` |

不要直接双击 `.c`。`.c` 只是工程里的一份源码；`.uvprojx` 才带着启动文件、芯片型号、编译器和库。

## 二、每次都这样打开

1. 进入要做的工程文件夹。
2. 双击里面唯一的 `.uvprojx`。
3. 左侧 Project 树里，展开 `01_我的代码`。
4. 双击 `led_blink.c` 或 `gpio_modes.c` 修改。

不要改 `Startup`、`System`、`Library`。它们是工程底座。

## 三、没有开发板：运行 Simulator

当前工程配置的是 Keil Simulator。

1. 按 `F7`：编译。
2. 确认 `Build Output` 是 `0 Error(s), 0 Warning(s)`。
3. 按 `Ctrl+F5`：进入或退出调试。
4. 进入调试后按 `F5`：运行。
5. 想看寄存器时，打开 `Peripherals → General Purpose I/O → GPIOC`，观察引脚位变化。

Simulator 能执行 CPU 指令和模拟外设，但板上的 LED 不会真的亮。想看实物，需要开发板。

## 四、有开发板：下载运行

1. 先确认板子的 LED 引脚和 ST-Link 接线。
2. `Project → Options for Target → Debug`。
3. 选择 `ST-Link Debugger`，接口选 `SW`。
4. 能识别芯片后，按 `F8` 下载。
5. 按板子复位键，程序开始运行。

`F7` 只是编译，`F8` 才是把程序写进芯片。

## 五、什么时候新建文件夹

**一个新的、能单独运行的 main 程序，对应一个新的工程文件夹。**

例如第 03 讲做按键输入，就新建：

```text
03_button_input\
  button_input.uvprojx
  button_input.c
  Startup\
  System\
  Library\
```

同一课里的小修改、小练习，仍然改当前文件夹里的 `gpio_modes.c`，不另开工程。

如果只是想写一份对照代码，可以：

- 在同一个工程里放进 `xx_demo.c`，但把它排除编译；
- 或另建独立工程。

绝不能把两个都参与编译、又都定义 `int main(void)` 的文件放进同一个工程。Keil 会把它们链接成同一个程序，入口重复。

## 六、文件命名

`.c` 文件名可以自己起，只要工程里的路径跟着更新：

```text
led_blink.c
gpio_modes.c
key_input.c
button_input.c
```

入口函数仍然必须叫：

```c
int main(void)
```

文件名和入口函数名是两笔账。
